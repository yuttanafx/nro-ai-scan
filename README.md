# NRO. AI กำลังฟัง (Next.js)

โลโก้จุดไข่ปลาเรืองแสงที่ตอบสนองต่อเสียง + ถอดเสียง + สรุปด้วย Claude ตามกรอบที่ตั้งไว้ + ส่ง Webhook

## ขึ้น Vercel
1. แตก zip แล้ว push ขึ้น GitHub (`git init && git add . && git commit -m init`)
2. Vercel → Add New → Project → เลือก repo นี้ (Framework: Next.js ตรวจอัตโนมัติ)
3. Settings → Environment Variables ใส่ค่าตาม `.env.example`
   - คีย์ AI อย่างน้อย 1 เจ้า: `ANTHROPIC_API_KEY` (Claude), `OPENAI_API_KEY` (GPT), `GEMINI_API_KEY` (Gemini) แล้วเลือกเจ้าที่ใช้ในหน้า ตั้งค่า → "AI ที่ใช้สรุป"
   - `ADMIN_USER`, `ADMIN_PASSWORD`, `SESSION_SECRET` (จำเป็น)
   - `USERS` บัญชีผู้ใช้ทั่วไป รูปแบบ `ชื่อ:รหัสผ่าน` คั่นหลายคนด้วย `,` เช่น `somchai:รหัสยาวๆ1,somsri:รหัสยาวๆ2` (ใส่แล้วต้อง Redeploy)
   - Storage → เพิ่ม **Upstash Redis** (Marketplace) เพื่อให้การตั้งค่าไม่หาย ตัวแปรจะถูกใส่ให้เอง
4. Deploy แล้วเปิดเว็บ
   - **ผู้ใช้ทั่วไป**: กด "เปิดไมค์" (หรือปุ่ม "เข้าสู่ระบบ" มุมขวาบน) จะมีป๊อปอัพให้กรอกชื่อและรหัสผ่านจาก `USERS` ใช้ไมค์และสั่งสรุปได้ แต่เข้าหน้าตั้งค่าไม่ได้
   - **แอดมิน**: ปุ่ม "ตั้งค่า" → ล็อกอินด้วย `ADMIN_USER` / `ADMIN_PASSWORD` (บัญชีแอดมินใช้ป๊อปอัพเปิดไมค์ได้เช่นกัน)

รันในเครื่อง: `npm install`, คัดลอก `.env.example` เป็น `.env.local` แล้วใส่ค่า, `npm run dev`
(ไมค์ต้องใช้ผ่าน HTTPS หรือ localhost เท่านั้น)

## โหมดโต้ตอบด้วยเสียง (พูดคุยกับ AI และให้ค้นฐานข้อมูล Supabase)
1. Vercel → Storage/Integrations → เชื่อมปลั๊กอิน **Supabase** เข้ากับโปรเจ็คนี้ (ตัวแปร `SUPABASE_URL` และคีย์จะถูกใส่ให้) แล้ว Redeploy
2. เข้า ตั้งค่า (แอดมิน) → ช่อง "ตาราง Supabase ที่ให้ AI อ่าน" ใส่ชื่อตาราง เช่น `cases, contacts` หรือจำกัดคอลัมน์ `cases(id,title,status)` แล้วบันทึก ถ้าเว้นว่าง AI จะอ่านฐานข้อมูลไม่ได้เลย
3. หน้าหลัก กดปุ่ม "โต้ตอบ: ปิด" ให้เป็น "เปิด" แล้วกด "เปิดไมค์" พูดแล้วหยุดสักครู่ AI จะค้นข้อมูลและพูดตอบ

หลักการทำงาน: คำพูดจบ → `/api/chat` ให้ AI ร่างแผนการค้น → เซิร์ฟเวอร์ตรวจกับรายการตาราง/คอลัมน์ที่อนุญาตแล้วค้นแบบ GET อย่างเดียว → AI ตอบสั้นๆ จากผลที่ได้ → เบราว์เซอร์อ่านออกเสียง (หยุดฟังระหว่างพูด)
ความปลอดภัย: ผู้ใช้ทั่วไปเห็นเฉพาะคำตอบ ไม่เห็นรายการตารางหรือคีย์ ไม่มีการเขียน/แก้/ลบข้อมูล ถ้ามีข้อมูลส่วนบุคคล ให้จำกัดคอลัมน์ในช่องนั้น และพิจารณาเปิด RLS ใน Supabase ใช้ `SUPABASE_ANON_KEY` แทน service role

## กรอกคีย์ API และเลือกเสียงพูดตอบในหน้าตั้งค่า (แอดมิน)
- ตั้งค่า → "คีย์ API และบริการภายนอก": กรอกคีย์ของ Anthropic, OpenAI, Gemini, GitHub, Azure Speech (Key + Region) และ Supabase (URL + Key) ได้ในหน้าเดียว
- คีย์ถูกเข้ารหัส (AES-256-GCM กุญแจมาจาก `SESSION_SECRET`) ก่อนเก็บใน Upstash Redis และไม่ถูกส่งกลับมาแสดงอีก เห็นแค่ 4 ตัวท้าย ช่องที่เว้นว่าง = ไม่เปลี่ยน มีปุ่ม "ลบ" ต่อช่อง
- ลำดับการใช้: ค่าที่กรอกในหน้าตั้งค่า → ถ้าไม่มีใช้ Environment Variables
- **ต้องต่อ Upstash Redis ก่อน** ถึงจะบันทึกคีย์ในหน้านี้ได้ (บน Vercel ถ้ายังไม่ต่อ ระบบจะไม่ให้บันทึก เพราะแต่ละ API เป็นคนละฟังก์ชัน หน่วยความจำใช้ร่วมกันไม่ได้)
- ถ้าเปลี่ยน `SESSION_SECRET` คีย์ที่บันทึกไว้จะถอดรหัสไม่ได้ ต้องกรอกใหม่
- "เสียงที่ AI พูดตอบ": เลือกเสียงในเครื่อง / OpenAI TTS / Azure Speech ใส่ชื่อเสียงได้ แล้วกด "บันทึกและทดสอบเสียง" ถ้าบริการเสียงมีปัญหา ระบบจะถอยกลับไปใช้เสียงในเครื่องเอง
- ใครมีสิทธิ์เข้า `/api/secrets` ได้บ้าง: เฉพาะแอดมินเท่านั้น

## โครงสร้าง
- `app/body.html`, `app/globals.css`, `public/app.js` หน้าเว็บ ลูกบอลและโลโก้จุด ตัวควบคุมฝั่งผู้ใช้
- `app/api/login|logout|me` ล็อกอินฝั่งเซิร์ฟเวอร์ แยก 2 บทบาท `admin` (ตั้งค่าได้) กับ `user` (ใช้ไมค์ได้) เก็บในคุกกี้ httpOnly ที่เซ็นด้วย HMAC
- `app/api/config` อ่าน/บันทึกการตั้งค่า (คนทั่วไปเห็นแค่ภาษาและชื่อฟิลด์ Webhook และ Authorization เห็นเฉพาะผู้ดูแล)
- `app/api/analyze` ต้องล็อกอิน (user หรือ admin) ถึงเรียกได้ เรียก AI สรุปตามฟิลด์ แล้วส่ง Webhook จากฝั่งเซิร์ฟเวอร์
- `app/api/chat` ตอบโต้ด้วยเสียง (ต้องล็อกอิน) ค้น Supabase แบบอ่านอย่างเดียวผ่าน `lib/supabase.ts`
- `app/api/secrets` (แอดมิน) กรอก/ลบคีย์ API, `app/api/tts` แปลงข้อความเป็นเสียงผ่าน OpenAI/Azure
- `lib/` ระบบ session, ที่เก็บค่า `store.ts`, คีย์เข้ารหัส `secrets.ts`, ตัวเรียก AI 3 เจ้า (`ai.ts`), ที่เก็บการตั้งค่า, ตัวจำกัดอัตรา
- `public/logo.jpg` โลโก้ (เปลี่ยนไฟล์นี้เพื่อเปลี่ยนโลโก้ ควรเป็นรูปวงกลมพื้นขาว)

## ก่อนเปิดให้คนทั่วไปใช้
- `/api/analyze` เปิดสาธารณะ (คนทั่วไปต้องใช้ได้โดยไม่ล็อกอิน) และจ่ายค่า API ของคุณ มีตัวจำกัด 10 ครั้ง/นาที/IP แต่เป็นแบบในหน่วยความจำ ถ้าเปิดจริงควรใช้ Upstash Ratelimit
- ล็อกอินมีตัวจำกัดการเดารหัสแบบเดียวกัน ใช้รหัสผ่านยาวและไม่ซ้ำ
- ช่องลิงก์รับได้ทั้งเว็บไซต์ทั่วไป (เช่น เว็บกฎหมาย/คำพิพากษา) และ GitHub สูงสุด 5 ลิงก์ ระบบดึงข้อความจากหน้าเว็บฝั่งเซิร์ฟเวอร์ (ไม่รองรับ PDF และหน้าที่โหลดข้อมูลด้วย JavaScript) รวมไม่เกิน 12,000 ตัวอักษร
- การดึงสคีมาจาก GitHub ทำฝั่งเซิร์ฟเวอร์ (`/api/github` เฉพาะผู้ดูแล) repo สาธารณะใช้ได้เลย ถ้า private ให้ตั้ง `GITHUB_TOKEN` (สิทธิ์อ่านอย่างเดียว)
- ลำดับการใช้งาน: วางลิงก์ GitHub → กด "ดึงจากลิงก์และให้ AI ร่างฟิลด์" → แก้ฟิลด์ → ใส่ Webhook URL (+ Authorization) → บันทึก → ทดสอบ Webhook
- Webhook ต้องเป็นปลายทางอื่น ไม่ใช่ `/api/analyze` ของเว็บนี้
- การถอดเสียงใช้ Web Speech API ของเบราว์เซอร์ (ดีที่สุดใน Chrome) ถ้าต้องการแม่นยำกว่านี้ ให้เปลี่ยนไปใช้บริการถอดเสียงฝั่งเซิร์ฟเวอร์
